# Twitch チャンネル自動録画

## 使い方

`python livecatch.py` または `python -m livecatch_core gui` の **Twitch自動録画** タブで、
チャンネル名やチャンネルURLを入力して「追加」します。空白・改行・カンマで複数登録できます。
動画URLやクリップURLではなく、`https://www.twitch.tv/チャンネル名` を登録してください。
大文字・小文字や同じチャンネルのURL表記が混ざっても重複登録しません。

1. 録画タブで保存先・画質・保存形式、必要ならGPU変換を設定。
2. 自動録画タブでチャンネルを追加し、確認間隔・同時自動録画上限を設定。
3. 「監視開始」を押す。すでに配信中なら初回確認後に録画を開始。
4. 次の配信も自動で録るには、アプリとPCを起動したままにする。

登録上限は50チャンネル、同時自動録画は既定3本・最大8本です。
確認間隔は既定60秒、30〜3600秒で設定できます。これは各チャンネルの通常時の確認間隔であり、
通知や録画開始をその秒数以内に保証するものではありません。確認プロセスは全体で最大2つなので、
多数登録・通信遅延・エラー時には検知が遅れます。古い確認予定から順番に処理します。

**アプリ終了中・PCの電源オフ／スリープ中には監視しません。**
「アプリ起動時に監視再開」はLiveCatch起動時の設定です。OSの自動起動／サービス登録ではありません。
既定では無効です。高負荷設定では起動時にも確認ダイアログが出る場合があります。

## 保存と録画の扱い

自動録画は検知後のライブHLSを対象にします。配信の過去部分をVODから遡って回収しません。
確認後から録画開始までに配信が切り替わった場合は、配信IDを照合して拒否し、次の確認を待ちます。

画質・保存先・一時保存先・Cookie設定・GPU変換などは「監視開始」時点の録画設定を使います。
監視中にGUIの通常設定を編集しても、動いている録画には適用されません。
自動録画のモードとファイル名は専用です。通常のカスタム出力テンプレートではなく、以下のように分離します。

```
保存先/Twitch/チャンネル名/配信ID_UTC時刻_一意な識別子/タイトル.mp4
```

保存形式がmkv/webmなら拡張子も変わります。再試行も別フォルダへ保存し、以前の録画を上書きしません。
録画失敗・強制停止で残った部分ファイルは自動削除しません。長時間運用では空き容量を確認してください。
録画後の結合・GPU変換中も、そのチャンネルは同時録画枠を使用します。
複数録画時には回線・ディスク・GPU負荷が合計されます。128並列設定が全体128並列という意味ではありません。

## 停止と再試行

- **監視だけ停止**：新しい配信の確認／自動起動を停止。録画・結合・変換中のものは継続。
- **監視・全自動録画停止**：監視を止め、全自動録画に通常停止を要求。手動録画は対象外。
- **選択の録画停止**：選択したチャンネルの録画を停止。同じ配信IDは自動で録り直さない。
- **選択の強制停止**：選択した録画プロセス群を終了。未完成ファイルが残る場合がある。
- **選択を再試行**：現在の配信のスキップ／失敗回数を解除し、新しい確認後に再試行。

チャンネルの追加・削除・有効／無効変更は監視を一旦停止し、確認プロセスの終了後に行ってください。
録画中のチャンネルを削除するには、その録画も先に停止します。無効化は次回の自動起動を止めるだけです。

同じアプリ内では1チャンネルに録画ワーカーを重複起動しません。手動録画中の同一チャンネルも除外します。
完了・手動停止済み配信IDと試行回数の履歴は、そのアプリ実行中だけ保持します。
アプリを再起動すると配信中のチャンネルを新しい部分録画として取得できます。複数のLiveCatchを同時起動した
場合のアプリ間排他は未実装なので、自動録画用アプリは1つだけ起動してください。

通信エラーを「オフライン」とは扱いません。確認エラーは間隔を延ばして再試行します。
録画失敗は同一配信IDにつき初回を含め最大3回まで試行し、その後は別の配信IDまたは手動再試行を待ちます。
別のチャンネルの確認失敗で、録画中の他チャンネルを停止しません。

## 実装と検証

追加のTwitch APIキーは不要です。固定依存のyt-dlpのTwitchStream抽出器でメタデータを確認します。
`UserNotLive` 型のエラーのみをオフラインと扱い、汎用エラーや文字列から推測しません。
署名付き動画URL・Cookie・全info_dictはGUIへ転送しません。認証／アクセス制限の回避はしません。
権利・アクセス許可のある配信を録画してください。

確認は既存のLiveCatchWorkerを`--twitch-probe`で起動し、45秒を超えたチェックを終了します。
録画は`--twitch-watch-record 配信ID`で別ワーカーを起動します。
GUIと録画ワーカーのexeを両方、新しいソースから再ビルドしてください。古いWorkerとの混在は非対応です。

新規テストは監視状態遷移、上限、停止後の結果無視、手動録画との排他、保存、プロセスIPC、
配信ID照合、GUI操作を検証します。実yt-dlpの型付きエラー／配信ID処理テストは抽出器の通信を置換して実行します。
実際のTwitch配信、Windowsの新しいexe、長時間同時録画の確認は別途必要です。
