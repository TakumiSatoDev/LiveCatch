# YouTube / Twitch 自動録画とバックグラウンド動作

## チャンネルを登録する

`python livecatch.py` または `python -m livecatch_core gui` で起動し、
**YouTube / Twitch 自動録画** タブにチャンネル名・URLを追加します。空白やカンマで複数登録できます。

| サービス | 入力例 |
|---|---|
| YouTube | `https://www.youtube.com/@handle`、`@handle`、`https://www.youtube.com/channel/UC...` |
| YouTubeの旧形式 | `/user/name`、`/c/name` を含む完全なチャンネルURL |
| Twitch | `https://www.twitch.tv/name`、`name`、`twitch:@name` |

統合画面では裸の `@handle` はYouTubeです。既存のTwitch登録はそのまま引き継ぎます。
動画・クリップ・再生リストURLの登録や、YouTubeアカウントの登録チャンネル一覧の自動インポートではありません。
追加のAPIキー・OAuthアプリ登録は不要です。

1. 録画タブで保存先・画質・保存形式・必要なCookie/GPU設定を選ぶ。
2. 自動録画タブでチャンネルを追加し、確認間隔・同時録画上限を設定する。
3. 「監視開始」を押す。配信中なら確認後に録画開始、配信前なら確認を繰り返す。

登録は両サービス合計50件、同時確認は2プロセス、自動録画は合計最大8本（既定3本）です。
確認間隔は既定60秒、最短30秒。多数登録や通信遅延・再試行ではさらに遅れるため、
**配信開始直後の検知や、指定秒数以内の録画開始を保証しません。**

### YouTubeの検知と保存

固定版yt-dlpでチャンネルの `/live` を確認します。動画への移動先は動画IDを検証して解決し、
実際のライブタブが返る場合も確認するエントリーは最大10件です。配信中を確認した動画だけを録画し、
開始予定は再確認、終了済み動画は録画しません。`UserNotLive` 型だけをオフラインと判定し、
通信・認証・不明な応答は確認エラーとして間隔を延ばします。

**各チャンネルで解決された1配信を対象とします。** 同じYouTubeチャンネルが複数配信を同時に行う場合、
全配信を網羅する機能ではありません。サイトの変更や取得制限はエラーとして表示します。

録画先は検知した動画IDに固定し、ダウンロード直前にID・取得元・配信中状態を再確認します。
検知後のライブを録画する方式で、以前のDVR全体やアーカイブをさかのぼって取得しません。
取得可能なライブバッファが一部重なる場合はあります。保存先は次のように分離します。

```
保存先/YouTube/チャンネルID/動画ID_UTC時刻_一意な識別子/タイトル.mp4
```

再試行も別フォルダです。従来の `.livecatch_twitch_watch.json` を共通の登録保存先として継続利用し、
YouTubeの登録は内部的に `youtube:` 接頭辞で区別します。監視開始時点の録画設定を使います。

同じ動画IDを指す複数の登録名は二重起動を抑制します。直近1,000件の完了・停止済みIDはメモリ上で保持し、
再起動後には引き継ぎません。手動録画のYouTube動画URL・同一チャンネル識別子も除外しますが、
未解決の別名までは一致判定できないため、1チャンネルを複数名で登録しないことを推奨します。

## Windowsトレイ常駐

**バックグラウンド** タブで「×ボタンで終了せずトレイに格納」にチェックし、**設定を適用**します。
以降は×ボタンで画面を閉じても、同じプロセスが監視・録画を続けます。既定では無効です。
トレイメニューから「表示」「監視開始」「監視だけ停止」「全自動録画を停止」「終了」を操作できます。

「監視だけ停止」は新規検知のみ停止し、録画中のものは継続します。「全自動録画を停止」は手動録画を止めません。
「終了」は画面を表示して、録画中であれば通常停止と後処理の完了を確認します。
停止しない録画には従来の明示的な強制停止を使います。後処理をタイマーで勝手に切断しません。
アプリ内更新は監視・自動録画・手動録画・後処理を停止してから実行してください。
更新処理中の新規監視・録画開始も禁止し、更新による録画の中断を防ぎます。

```powershell
python livecatch.py --background
python -m livecatch_core gui --background
```

`--background` や「次回はトレイに格納して起動」は、**トレイの準備完了後にだけ画面を隠します**。
依存不足・初期化失敗・タイムアウト・トレイ終了時は画面を残すか復帰させます。初期化中に画面が一瞬表示される場合があります。
トレイ側のコールバックはキューへ命令を入れるだけで、Tkの操作はGUIスレッドで行います。

今回のネイティブトレイ対応は **Windowsのみ** です。他OSは通常GUIまたは後述のGUIなし監視を使ってください。
**画面オフ・ウィンドウ非表示は可能ですが、PCのスリープ・電源オフ・サインアウト中は監視できません。**
スリープ抑制、スリープ解除、Windowsサービス登録は行いません。

新しいGUIとGUIなし監視は共通のプロセスロックを保持し、二重起動を拒否します。
クラッシュ時はOSがロックを解放します。起動中にロックファイルを削除しないでください。
旧バージョンはこの排他に参加しないため、旧版と新版を同時に起動しないでください。

## Windowsログイン時の起動

「Windowsログイン時に起動」を有効にして「設定を適用」すると、現在のユーザーの
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に `LiveCatchAutoRecord` の1項目だけを登録します。
チェックを外して適用すると、その項目だけを削除します。管理者権限は不要です。
パスは引用符付きで組み立て、Windows Runの上限である260文字を超えるコマンドは拒否します。
アンインストール・移動前にはこの設定を解除してください。

**起動後の自動監視には、自動録画タブの「アプリ起動時に監視再開」も有効にして保存してください。**
ログイン時起動だけでは監視は始まりません。高負荷設定時の確認を自動承認する機能もありません。

## GUIなし監視

```powershell
python -m livecatch_core watch
python -m livecatch_core watch --config "settings.json" --watch-config "channels.json"
```

GUIを作らないフォアグラウンドプロセスです。端末・プロセスを動かしたままにするか、別途サービス管理機能で起動してください。
このコマンドの明示的な実行では、GUIの起動時監視チェックによらず、保存済みの有効チャンネルを監視します。
高負荷設定を使う場合は `--allow-extreme` が必要です。1回目のCtrl+C/SIGTERMで通常停止、2回目でワーカーを強制停止します。
ログは既存の秘匿処理付きJSON形式です。デーモンやOSサービスを自動インストールするコマンドではありません。

## 依存・配布・検証範囲

更新後に `python -m pip install -r requirements.txt` を実行してください。
Windowsではpystray 0.19.5とPillowを追加します。トレイのライブラリは必要になるまで読み込みません。
両Windowsビルドスクリプトへトレイバックエンドと画像ライブラリの収集設定を追加しています。
**LiveCatch.exeとLiveCatchWorker.exeを両方再ビルド**してください。古いWorkerとの混在は非対応です。
ソースの更新と、新バージョンのタグ・インストーラー公開は別の作業です。

追加テストは入力検証、既存設定の保持、サービス共通の上限、ID重複、遅延応答、録画直前の検証、
プロセス排他、起動登録の明示操作、トレイ準備・失敗、実Tkによる非表示・復帰と監視継続を対象にします。
yt-dlp契約テストは抽出器の通信を置換し、GUIテストのトレイとレジストリも模擬実装です。
**CI成功は、実YouTube配信・Windows実トレイ・再ビルドしたインストーラーの動作確認を意味しません。**
実アカウント、長時間録画、スリープ復帰、配布exeは実機確認が別途必要です。
