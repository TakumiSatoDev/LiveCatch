# LiveCatch

**YouTube・Twitchの配信や動画を、手動でも自動でも保存できるWindowsアプリです。**

チャンネルを登録しておくと、配信開始を定期的に確認して自動録画します。通常の録画にGPUは必要ありません。映像・音声は追加の再エンコードをせず保存します。

## はじめる

初めて使う方は [最新版のダウンロード](https://github.com/TakumiSatoDev/LiveCatch/releases/latest) から `LiveCatch-Setup-バージョン番号.exe` を実行してください。録画に必要なFFmpeg・ffprobe・DenoはWindows配布版に含まれます。

すでにインストールしている方は、アプリ右上の **「更新を確認」→「更新する」** で更新できます。監視・録画・結合が終わってから更新してください。`Update-*.zip` はアプリが使う更新パッケージです。通常は自分で解凍する必要はありません。

## まず1本、録画する

1. **「設定」** で保存先と画質を選び、**「保存・画質・取得設定を保存」** を押します。迷ったら `recommended_1080p` のままで大丈夫です。
2. **「録画」** に動画または配信のURLを貼り、モードを選びます。
3. **「開始」** を押します。終了後は **「保存先を開く」** から動画を確認できます。

| モード | こんなときに使う |
|---|---|
| `reservation`（予約） | 配信待機ページなど、URLが分かっている配信を待ちたいとき。チャンネルの常時監視は自動録画タブを使います。 |
| `live_full`（終了まで） | 取得できる過去部分から、配信終了まで残したいとき。 |
| `catchup_stop`（現在まで） | YouTubeのDVRで、取得開始時に確認できた共通地点まで保存して止めたいとき。進行中のTwitch配信には使えません。 |

終了済み動画もURLから取得できます。配信の過去部分をさかのぼれるかは、配信者・サービス側のDVRやVODの公開状況によります。公開されていない部分は復元できません。

**通常は「停止」を使ってください。** 保存と結合を終えてから停止します。「強制停止」は処理を直ちに打ち切るため、未完成のファイルが残ることがあります。

## チャンネルを登録して自動録画する

**「YouTube / Twitch 自動録画」** にチャンネル名やURLを入力して **「追加」→「監視開始」**。空白やカンマで複数まとめて登録できます。

| サービス | 登録するものの例 |
|---|---|
| YouTube | `@チャンネルのハンドル` または `https://www.youtube.com/@handle` |
| Twitch | `チャンネル名` または `https://www.twitch.tv/name` |

YouTubeアカウントの「登録チャンネル一覧」を取り込む機能ではありません。LiveCatchの一覧に登録してください。

監視中でもチャンネルを追加できます。追加分は次の確認候補に入りますが、同時確認は2件なので混雑時は順番待ちになります。登録は合計50件、自動録画は最大8本です。既定では60秒間隔で確認し、最大3本を同時録画します。配信開始の瞬間に必ず検知する仕組みではありません。

| 追いつき設定 | 動作 |
|---|---|
| `from_start` | 公開されている過去部分から取得を試みます。YouTubeはDVR、Twitchは配信に関連するVODの有無に依存します。 |
| `live_edge` | 検知した時点付近から録画します。 |

「監視だけ停止」は、これからの確認を止めます。進行中の録画は継続します。録画も止めるときは「監視・全自動録画停止」、1チャンネルだけ止めるときは一覧で選択して「選択の録画停止」を使います。自動録画タブにも **「保存先を開く」** があります。

## `recommended` と `best`、どちらを選ぶ？

| 画質 | 違い | 向いている使い方 |
|---|---|---|
| `recommended_1080p` | **1080p以下**から最良の映像・音声を選びます。 | 取得時間・保存容量と画質のバランスを取りたい。 |
| `best` | **解像度に上限を設けず**、取得可能な最良の映像・音声を選びます。4Kなどがあれば対象になります。 | 元配信に近い最高画質を優先して残したい。 |
| `720p` / `480p` など | 指定した高さ以下から選びます。 | データ量を抑えたい、複数録画を軽くしたい。 |

**速度・容量優先なら `recommended_1080p`、最高画質優先なら `best`。** 元配信の最高画質が1080pなら、同じ映像が選ばれることもあります。`best` にしても元配信以上に高画質になるわけではありません。

画質は「ダウンロードする映像の選択」です。保存後にGPUで縮小する設定ではありません。指定上限に合う映像がない場合はエラーにし、黙って上限超えの映像へ切り替えません。画質指定とMP4/MKV/WebMの保存形式は別の設定です。端末や編集ソフトが取得したコーデックに対応しているかも確認してください。

### 100%のあとに処理が続くことがあるのは？

YouTubeでは高画質の映像と音声が別ストリームになっていることがあり、最後にFFmpegで**再エンコードせず1本へ結合**します。これは画質を上げる処理ではありませんが、1本の再生可能な動画にするため必要です。

一方、動画ファイル内部へのメタデータ埋め込みは画質に影響せず、大きな動画ではファイル全体をもう一度読み書きします。そのため **v3.5.1から既定OFF** です。必要な場合だけ「設定」→「メタデータを動画へ埋め込む（完了後に全体を書き直す）」をONにしてください。`info.json` はこの設定とは別で、ONのまま利用できます。

処理中に見える `.temp.mp4` はメタデータ埋め込み等のFFmpeg処理用一時ファイルです。既定設定ではこの追加の全体再書き込みは発生しません。

## 進捗の見方

手動録画・自動録画は同じ進捗処理を使います。通信量が増えているのにfragment数だけ止まって見える状態を判断できるよう、**「取得」と「保存」を分けています。**

```text
取得 120 / 保存 96 frag · 保存待ち 24 · 256 MiB · 18 MiB/s
```

「取得」はダウンロード済みの断片数、「保存」は順番どおり動画へ追記した断片数です。後ろの断片が先に取得できても、先頭の断片を待っている間は保存数が進みません。通信の進行中は受信量や速度も表示します。再開時は今回の取得・追記数と位置を区別します。

追いつき率を取得できるYouTube DVRでは **「追いつき 63%」→「LIVE」** と表示します。音声・映像の両方を確認し、最後に観測したライブ位置との距離から計算します。配信が進むにつれて分母も増えるため、割合が少し戻る場合があります。「LIVE」は残り約2断片以内という目安で、遅延ゼロを保証しません。

配信情報の取得・結合など、全体量が分からない処理は **`…`** で表示します。別の処理で出た100%をそのまま使い回しません。外部FFmpegなどfragment数を通知しない経路もあるため、数値が出ないことだけで停止とは判断できません。経過時間・ログも確認してください。

## 速くする設定

並列数は、多くすれば必ず速くなる設定ではありません。**同じ対象・同じ画質で、取得完了までの時間を比較**してください。ライブ位置に追いついた後は、配信の生成速度を超えて未来の映像を取得することはできません。

| 環境・使い方 | 試し始める並列数 / prefetch |
|---|---|
| 軽いPC、遅めの回線 | `8～16 / 2` |
| 一般的なPC・SSD | `16～32 / 2～3` |
| 高速回線・NVMeに余裕がある | `64 / 4` から実測し、`96～128` と比較 |
| 上限を試す実験 | `192～256 / 4～8`。最初は録画1本だけで確認 |

これは性能保証ではなく、比較の開始点です。429・タイムアウト・CPU負荷・保存待ちが増える、あるいは完了が遅くなるなら一段下げます。自動録画では設定が**録画1本ごと**に使われます。

監視専用プリセットは `balanced=32/3`、`fast=64/4`、`extreme=96/6`、`max=128/8`、`ultra=192/8`、`experimental_256=256/8`。`manual` は手動録画の並列設定を使います。新規の監視設定は `fast` ですが、必ず最速とは限りません。

### SSDへの書き込みに波があるのは？

取得した断片は一時ファイルへ書き込み、順番がそろったものから動画へ追記します。先読み分が全部たまるまで待って一括保存する設計ではありません。ただし先頭断片の遅延・再試行、音声と映像の進み方、OSの書き込みキャッシュ、最後の結合処理で波が出ます。

毎回SSDへの物理書き込みを強制すれば速い、というわけではありません。通常のバッファ付き書き込みと断片ごとの追記を維持し、追加の細かな `fsync` は入れていません。表示上の「保存」はアプリが追記した量であり、停電に耐える物理書き込み完了の保証ではありません。

保存先がHDDやNASで遅い場合は、高速なSSDを一時保存先にする方法があります。ただし別ドライブへ移動する際は最後にコピーが必要になるため、全体では遅くなる場合もあります。

## 保存場所とバックグラウンド動作

動画は保存先の `YouTube` / `Twitch` 以下で、チャンネル・配信ごとに分かれます。手動録画と自動録画ではチャンネルの識別子が異なる場合があります。既存動画の移動や独自テンプレートの書き換えは行いません。

Windowsでは「設定」のバックグラウンド欄で、×ボタンをトレイ格納にできます。**ウィンドウを閉じる・画面を消すのはOKですが、PCのスリープ・電源オフ・サインアウト中は動きません。** ログイン時に監視も始めるには、「Windowsログイン時に起動」と「アプリ起動時に監視再開」の両方が必要です。高負荷確認ダイアログが出る設定では操作が必要になります。

## 困ったとき

| 症状 | まず確認すること |
|---|---|
| 取得が遅い・429が増える | 並列数を下げ、同時録画数を減らして比較。サイト側の制限を回避する機能はありません。 |
| 取得は進むが保存数が止まる | 先頭断片の再試行や保存待ちを確認。断片を飛ばして成功扱いにはしません。 |
| ChromeのCookie取得に失敗 | まずCookieを使わずに取得できる公開対象か確認。認証が必要ならブラウザのロックや権限を確認。 |
| 日本語が文字化けする | アプリを更新し、GUIとWorkerを同じバージョンにそろえる。設定ファイルはUTF-8で保存。すでに `�` に置換された文字は復元できない場合があります。 |
| 更新できない | 監視・録画・結合を終了して再確認。ソース版は実行ファイルの自動置換対象ではありません。 |
| 保存形式・結合でエラー | コーデックと保存形式の組み合わせ、空き容量、ログを確認。元ファイルを消す前に状態を調べてください。 |

詳しい仕組みやソースからの起動は [開発者向けガイド](docs/DEVELOPMENT.md)、監視・トレイの詳細は [自動録画ガイド](docs/YOUTUBE_BACKGROUND.md) を参照してください。
